Routing rules (meeting thesis)

  • Default = Sonnet — everyday coding, refactors, reviews, drafts. Best $/intelligence for most harness work.
  • Escalate = Opus — ambiguous design, multi-file root-cause, security-sensitive diffs, “stuck after 2 Sonnet attempts.”
  • Bulk = Haiku / Flash / Luna / nano — classify, summarize, extract, format. Don’t burn frontier tokens on glue.
  • Cache & batch — repeated system prompts and offline jobs often beat “pick a cheaper model” alone (Anthropic cache reads ~10% of input; Gemini/xAI batch/flex discounts vary).
  • Harness > model — a tight skill + good tests on Sonnet often beats Opus on a sloppy prompt. Spend budget on context quality, not only model tier.

Four sub-groups

Agenda map for the meeting — same budget, sharper allocation.

1 · Models & harnesses

Which models are wired into Cursor / Claude Code / Argus / internal bots. Defaults, max mode, thinking effort. Price board is the shared scoreboard.

2 · Our skills

Reusable playbooks that cut retries. A good skill on Sonnet beats a vague prompt on Opus. Cost lives in turns, not just $/MTok.

3 · Argus adoption & new use cases

Where the team still under-uses agents (ops, triage, docs) vs overspends (frontier on glue work). New cases should ship with a default model + escalate path.

4 · Routing, cost + common toolbox

Shared calculator, price board, and “Sonnet → Opus” rules. One toolbox so everyday price checks don’t live in someone’s head.
